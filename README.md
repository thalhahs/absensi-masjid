# Absensi Masjid

Aplikasi absensi masjid berbasis web yang menggunakan QR code untuk presensi petugas shalat. Dibangun dengan Next.js dan Supabase.

## Fitur

- **Autentikasi PIN 6 digit** — petugas login tanpa password, hanya PIN
- **QR Code per petugas** — superadmin generate QR khusus untuk setiap petugas
- **Scan QR via kamera HP** — petugas scan QR masjid, lalu verifikasi PIN untuk absen
- **Verifikasi identitas** — QR tidak bisa dipakai oleh petugas lain
- **Attendance window** — absen hanya diterima dalam jendela waktu tertentu (10 menit sebelum adzan sampai iqomah)
- **Auto ALFA** — otomatis menandai ALFA untuk petugas yang tidak absen setelah window tutup
- **Jadwal shalat otomatis** — sinkron dengan API MyQuran
- **Reminder adzan** — notifikasi 15 menit sebelum adzan
- **Role-based access** — superadmin, officer, dan masjid dengan akses berbeda
- **Riwayat & statistik** — export CSV, ringkasan hadir/alfa, hadir rate

## Installation

### 1. Clone repository

```bash
git clone <repository-url>
cd absensi-masjid
```

### 2. Install dependencies

```bash
npm install
```

### 3. Setup environment variables

Buat file `.env.local` di root project:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

NEXT_PUBLIC_MOSQUE_CITY_ID=1301
NEXT_PUBLIC_MOSQUE_CITY_NAME=KOTA%20JAKARTA
NEXT_PUBLIC_MOSQUE_NAME=Masjid%20Ash-Sholihin
NEXT_PUBLIC_MOSQUE_AREA=Kalibata%20Indah%2C%20Jakarta%20Selatan
```

### 4. Setup database

Jalankan SQL di **Supabase Dashboard → SQL Editor**:

```sql
-- 1. Tabel petugas
create table if not exists public.officers (
  id bigint generated by default as identity primary key,
  name text not null unique,
  active boolean not null default true,
  role text not null default 'officer' check (role in ('superadmin', 'officer', 'masjid')),
  pin_hash text not null default '',
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- 2. Tabel jadwal harian
create table if not exists public.schedule_assignments (
  id bigint generated by default as identity primary key,
  date date not null,
  prayer_id text not null check (prayer_id in ('subuh','dzuhur','ashar','maghrib','isya')),
  imam_id bigint references public.officers(id) on delete set null,
  muadzin_id bigint references public.officers(id) on delete set null,
  badal_imam_id bigint references public.officers(id) on delete set null,
  unique(date, prayer_id)
);

-- 3. Tabel absensi
create table if not exists public.attendance (
  id bigint generated by default as identity primary key,
  officer_id bigint references public.officers(id) on delete set null,
  officer_name text not null,
  role text not null check (role in ('Imam','Muadzin','Badal Imam')),
  prayer text not null,
  prayer_time text not null,
  status text not null check (status in ('HADIR','TERLAMBAT','ALFA')),
  scan_time text not null,
  attendance_date date not null,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

alter table if exists public.attendance add column if not exists officer_id bigint references public.officers(id) on delete set null;

-- 3.5. Tabel QR token untuk absensi via scan
create table if not exists public.qr_tokens (
  id bigint generated by default as identity primary key,
  token text unique not null,
  officer_id bigint references public.officers(id) on delete set null,
  officer_name text not null,
  role text not null check (role in ('Imam','Muadzin','Badal Imam')),
  prayer text not null,
  prayer_time text not null,
  attendance_date date not null,
  used boolean not null default false,
  used_at timestamp with time zone,
  expires_at timestamp with time zone not null,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

alter table if exists public.qr_tokens add column if not exists officer_id bigint references public.officers(id) on delete set null;

-- 4. Index untuk performa
drop index if exists idx_schedule_assignments_date_prayer;
drop index if exists idx_attendance_date_officer;
drop index if exists idx_qr_tokens_token;

create index if not exists idx_schedule_assignments_date_prayer on public.schedule_assignments(date, prayer_id);
create index if not exists idx_attendance_date_officer on public.attendance(attendance_date, officer_id);
create index if not exists idx_qr_tokens_token on public.qr_tokens(token);

-- 5. RLS
alter table public.officers enable row level security;
alter table public.schedule_assignments enable row level security;
alter table public.attendance enable row level security;
alter table public.qr_tokens enable row level security;

-- 6. Policy untuk officers
drop policy if exists "Public read officers" on public.officers;
drop policy if exists "Public insert officers" on public.officers;
drop policy if exists "Public update officers" on public.officers;
drop policy if exists "Public delete officers" on public.officers;

create policy "Public read officers" on public.officers for select using (true);
create policy "Public insert officers" on public.officers for insert with check (true);
create policy "Public update officers" on public.officers for update using (true);
create policy "Public delete officers" on public.officers for delete using (true);

-- 7. Policy untuk schedule_assignments
drop policy if exists "Public read schedule_assignments" on public.schedule_assignments;
drop policy if exists "Public insert schedule_assignments" on public.schedule_assignments;
drop policy if exists "Public update schedule_assignments" on public.schedule_assignments;
drop policy if exists "Public delete schedule_assignments" on public.schedule_assignments;

create policy "Public read schedule_assignments" on public.schedule_assignments for select using (true);
create policy "Public insert schedule_assignments" on public.schedule_assignments for insert with check (true);
create policy "Public update schedule_assignments" on public.schedule_assignments for update using (true);
create policy "Public delete schedule_assignments" on public.schedule_assignments for delete using (true);

-- 8. Policy untuk attendance
drop policy if exists "Public read attendance" on public.attendance;
drop policy if exists "Public insert attendance" on public.attendance;
drop policy if exists "Public update attendance" on public.attendance;
drop policy if exists "Public delete attendance" on public.attendance;

create policy "Public read attendance" on public.attendance for select using (true);
create policy "Public insert attendance" on public.attendance for insert with check (true);
create policy "Public update attendance" on public.attendance for update using (true);
create policy "Public delete attendance" on public.attendance for delete using (true);

-- 9. Policy untuk qr_tokens
drop policy if exists "Public read qr_tokens" on public.qr_tokens;
drop policy if exists "Public insert qr_tokens" on public.qr_tokens;
drop policy if exists "Public update qr_tokens" on public.qr_tokens;
drop policy if exists "Public delete qr_tokens" on public.qr_tokens;
```

## User Roles

| Role | Deskripsi | Akses |
|---|---|---|
| **superadmin** | Administrator masjid | Kelola petugas, kelola jadwal, generate QR, lihat statistik, export CSV |
| **officer** | Petugas shalat | Scan QR untuk presensi, lihat jadwal, lihat profile |
| **masjid** | Operator kiosk masjid | Generate QR, lihat jadwal, lihat riwayat |

## Login PIN

- PIN di-hash menggunakan PBKDF2-SHA512 dengan salt acak
- Default admin PIN: `123580`
- PIN untuk officer di-generate otomatis berdasarkan nama (hash MD5 → 6 digit angka)
- Setiap officer bisa mengganti PIN melalui panel admin

## Alur Presensi

```
1. Superadmin buka halaman Presensi
2. Pilih shalat yang aktif
3. Klik tombol QR pada petugas yang ingin di-presensi-kan
4. QR code muncul di layar (berisi token + officer_id + prayer)
5. Petugas buka HP, scan QR dengan kamera
6. Browser membuka /approve/{token}
7. Jika belum login → minta PIN 6 digit
8. Cek: session.officerId === token.officer_id?
   - YA → tampilkan konfirmasi absensi
   - TIDAK → tolak akses
9. Petugas klik "Setuju / Approve"
10. Attendance tercatat sebagai HADIR
```

## Attendance Window

| Role | Window |
|---|---|
| Imam | 10 menit sebelum adzan → 5 menit setelah adzan |
| Muadzin | 10 menit sebelum adzan → adzan |
| Badal Imam | 10 menit sebelum adzan → 5 menit setelah adzan |

Window tiap shalat dihitung dari jadwal MyQuran. Scan di luar window ditolak.

## Auto ALFA

Setiap 1 detik, aplikasi mengecek apakah window untuk setiap shalat sudah tertutup. Jika ya, dan belum ada record attendance untuk officer tersebut, sistem otomatis insert record `ALFA` via `/api/alfa`.
